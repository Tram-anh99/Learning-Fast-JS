# Hệ Thống Cơ Sở Dữ Liệu Quản Lý Nông Sản - Hoàn Chỉnh

## Tổng Quan

Cơ sở dữ liệu được thiết kế theo **3 chuẩn hóa (3NF)** tích hợp đầy đủ các hệ thống:

1. **MSVT** - Mã số vùng trồng & truy xuất nguồn gốc
2. **Giống cây trồng** - Quản lý nguồn gen & giống bảo hộ
3. **Phân bón** - Danh mục phân bón & cơ sở kinh doanh
4. **Thuốc BVTV** - Thuốc bảo vệ thực vật
5. **Cơ sở** - Cơ sở sản xuất kinh doanh
6. **Vùng trồng** - Vùng trồng & nhật ký canh tác

## Sơ Đồ Quan Hệ Chi Tiết

### 1. Module Danh Mục Cơ Bản

```
tinh (Tỉnh/TP)
 └─> huyen (Quận/Huyện)
      └─> xa (Phường/Xã)

trang_thai_vung (Trạng thái vùng)
trang_thai_ma_vung (Trạng thái mã vùng)
chung_nhan (Chứng nhận: VietGAP, GlobalGAP...)
thi_truong (Thị trường xuất khẩu)
loai_hoat_dong (Loại hoạt động canh tác)
```

### 2. Module Giống Cây Trồng & Nguồn Gen

```
nhom_cay (Nhóm cây: ăn quả, lúa, rau củ...)
 └─> loai_cay (Loại cây trồng)
      ├─> nguon_gen (Nguồn gen GBVN)
      │    ├─> co_quan_luu_tru_gen
      │    ├─> noi_thu_thap_gen
      │    └─> nguon_thu_thap
      └─> giong_bao_ho (Giống bảo hộ PVPO)
```

**Giải thích chuẩn hóa:**
- **1NF**: Tách thông tin nguồn gen thành các bảng riêng
- **2NF**: Cơ quan lưu trữ, nơi thu thập là bảng độc lập
- **3NF**: Không có phụ thuộc bắc cầu

### 3. Module Tổ Chức & Cơ Sở

```
to_chuc_ca_nhan (Tổ chức/Cá nhân: HTX, DN, Nông dân...)
 └─> co_so (Cơ sở SX/KD)
      └─> loai_hinh_co_so
           ├─> CS_GIONG (Cơ sở giống)
           ├─> CS_PB (Cơ sở phân bón)
           ├─> CS_TBVTV (Cơ sở thuốc BVTV)
           ├─> CS_DONG_GOI (Cơ sở đóng gói)
           └─> CS_CHE_BIEN (Cơ sở chế biến)
```

**Giải thích:**
- Một tổ chức có thể quản lý nhiều cơ sở
- Một cơ sở chỉ thuộc một loại hình
- Tách bảng `to_chuc_ca_nhan` để tránh lặp thông tin (3NF)

### 4. Module Phân Bón

```
loai_phan_bon (Loại: hữu cơ, NPK, vi lượng...)
 └─> phan_bon (Danh mục phân bón)
      ├─> phan_bon_luu_hanh (Công bố hợp quy)
      │    ├─> to_chuc_cong_bo (FK)
      │    └─> to_chuc_chung_nhan (FK)
      └─> co_so_phan_bon (N-N: Cơ sở SX/KD)
           └─> co_so (FK)
```

**Quan hệ N-N:**
- Một cơ sở có thể SX/KD nhiều loại phân bón
- Một loại phân bón có thể được SX/KD bởi nhiều cơ sở

### 5. Module Thuốc BVTV

```
nhom_thuoc_bvtv (Nhóm: trừ sâu, diệt nấm, diệt cỏ...)
 └─> thuoc_bvtv (Danh mục thuốc)
      ├─> thuoc_bvtv_luu_hanh (Đăng ký lưu hành)
      │    └─> to_chuc_cong_bo (FK)
      └─> co_so_thuoc_bvtv (N-N: Cơ sở SX/KD)
           └─> co_so (FK)
```

**Trạng thái thuốc:**
- `duoc_su_dung`: Được phép sử dụng
- `cam_su_dung`: Cấm sử dụng

### 6. Module Vùng Trồng (MSVT)

```
vung_trong (Vùng trồng)
 ├─> toa_do_vung (Tọa độ polygon)
 ├─> chu_so_huu (FK: to_chuc_ca_nhan)
 ├─> trang_thai (FK)
 ├─> chung_nhan (FK)
 │
 ├─> vung_cay_trong (N-N: Cây trồng)
 │    ├─> loai_cay (FK)
 │    ├─> giong_bao_ho (FK - optional)
 │    └─> vung_thi_truong (N-N: Thị trường)
 │         └─> thi_truong (FK)
 │
 └─> vung_co_so_dong_goi (N-N: Cơ sở đóng gói)
      └─> co_so (FK)
```

**Giải thích chuẩn hóa:**
- **1NF**: Tọa độ polygon tách thành bảng riêng (mỗi điểm 1 dòng)
- **2NF**: Thông tin cây trồng tách thành bảng `vung_cay_trong`
- **3NF**: Thị trường xuất khẩu là bảng quan hệ N-N riêng

### 7. Module Nhật Ký Canh Tác

```
lich_su_canh_tac (Nhật ký đồng ruộng)
 ├─> vung_trong (FK)
 ├─> loai_hoat_dong (FK)
 ├─> phan_bon (FK - optional)
 └─> thuoc_bvtv (FK - optional)

diem_sau_benh (Điểm phát sinh sâu bệnh)
 ├─> vung_trong (FK)
 └─> thuoc_bvtv_su_dung (FK - optional)
```

## Phân Tích Chuẩn Hóa

### Chuẩn 1 (1NF) - Giá trị nguyên tử

**Vấn đề ban đầu:**
```javascript
// Mock data có mảng
thiBruongXuatKhau: ["Trung Quốc", "Hoa Kỳ", "EU"]
toaDo: [[10.762, 106.66], [10.77, 106.67], ...]
```

**Giải pháp:**
```sql
-- Tách thành bảng quan hệ N-N
CREATE TABLE vung_thi_truong (
    vung_cay_trong_id INTEGER,
    thi_truong_id INTEGER
);

-- Tách tọa độ thành từng điểm
CREATE TABLE toa_do_vung (
    vung_trong_id INTEGER,
    thu_tu INTEGER,
    vi_do DECIMAL,
    kinh_do DECIMAL
);
```

### Chuẩn 2 (2NF) - Phụ thuộc hoàn toàn vào khóa chính

**Vấn đề:** Thông tin loại cây lặp lại trong nhiều vùng

**Giải pháp:**
```sql
-- Tách thành bảng độc lập
CREATE TABLE loai_cay (
    id SERIAL PRIMARY KEY,
    ma_cay VARCHAR(20),
    ten_cay VARCHAR(100),
    ten_khoa_hoc VARCHAR(200)
);

-- Bảng trung gian
CREATE TABLE vung_cay_trong (
    vung_trong_id INTEGER,
    loai_cay_id INTEGER,
    dien_tich DECIMAL,
    nang_suat DECIMAL
);
```

### Chuẩn 3 (3NF) - Không phụ thuộc bắc cầu

**Vấn đề:** Thông tin trạng thái (tên, màu, CSS) lặp lại

**Giải pháp:**
```sql
-- Tách thành bảng tham chiếu
CREATE TABLE trang_thai_vung (
    id SERIAL PRIMARY KEY,
    ma_trang_thai VARCHAR(20),
    ten_trang_thai VARCHAR(50),
    mau_sac VARCHAR(10),
    css_class VARCHAR(30)
);

-- Vùng trồng chỉ tham chiếu
CREATE TABLE vung_trong (
    id SERIAL PRIMARY KEY,
    trang_thai_id INTEGER REFERENCES trang_thai_vung(id)
);
```

### 4. Truy Vấn Mẫu

#### Lấy danh sách vùng trồng đầy đủ

```sql
SELECT * FROM nongsan.v_vung_trong_full;
```

#### Lấy cây trồng theo vùng

```sql
SELECT 
    vt.ma_vung,
    vt.ten_vung,
    lc.ten_cay,
    vct.dien_tich,
    vct.nang_suat
FROM nongsan.vung_cay_trong vct
JOIN nongsan.vung_trong vt ON vct.vung_trong_id = vt.id
JOIN nongsan.loai_cay lc ON vct.loai_cay_id = lc.id
WHERE vt.ma_vung = 'VT-001';
```

#### Lấy thị trường xuất khẩu của vùng

```sql
SELECT 
    vt.ma_vung,
    vt.ten_vung,
    lc.ten_cay,
    tt.ten_thi_truong
FROM nongsan.vung_thi_truong vtt
JOIN nongsan.vung_cay_trong vct ON vtt.vung_cay_trong_id = vct.id
JOIN nongsan.vung_trong vt ON vct.vung_trong_id = vt.id
JOIN nongsan.loai_cay lc ON vct.loai_cay_id = lc.id
JOIN nongsan.thi_truong tt ON vtt.thi_truong_id = tt.id
WHERE vt.ma_vung = 'VT-001';
```

#### Lịch sử canh tác với vật tư

```sql
SELECT 
    lsc.ngay_thuc_hien,
    lhd.ten_loai AS hoat_dong,
    lsc.tieu_de,
    lsc.noi_dung,
    pb.ten_phan_bon,
    lsc.lieu_luong_phan_bon,
    tb.ten_thuoc AS thuoc_bvtv,
    lsc.lieu_luong_thuoc
FROM nongsan.lich_su_canh_tac lsc
JOIN nongsan.vung_trong vt ON lsc.vung_trong_id = vt.id
LEFT JOIN nongsan.loai_hoat_dong lhd ON lsc.loai_hoat_dong_id = lhd.id
LEFT JOIN nongsan.phan_bon pb ON lsc.phan_bon_id = pb.id
LEFT JOIN nongsan.thuoc_bvtv tb ON lsc.thuoc_bvtv_id = tb.id
WHERE vt.ma_vung = 'VT-001'
ORDER BY lsc.ngay_thuc_hien DESC;
```

#### Thống kê cơ sở theo loại hình

```sql
SELECT 
    lh.ten_loai,
    COUNT(cs.id) AS so_luong,
    COUNT(CASE WHEN cs.tinh_trang = 'con_hieu_luc' THEN 1 END) AS con_hieu_luc,
    COUNT(CASE WHEN cs.tinh_trang = 'het_hieu_luc' THEN 1 END) AS het_hieu_luc
FROM nongsan.co_so cs
JOIN nongsan.loai_hinh_co_so lh ON cs.loai_hinh_id = lh.id
GROUP BY lh.ten_loai;
```

#### Phân bón/thuốc được sử dụng nhiều nhất

```sql
-- Phân bón
SELECT 
    pb.ten_phan_bon,
    lpb.ten_loai AS loai,
    COUNT(lsc.id) AS so_lan_su_dung
FROM nongsan.lich_su_canh_tac lsc
JOIN nongsan.phan_bon pb ON lsc.phan_bon_id = pb.id
LEFT JOIN nongsan.loai_phan_bon lpb ON pb.loai_phan_bon_id = lpb.id
GROUP BY pb.id, pb.ten_phan_bon, lpb.ten_loai
ORDER BY so_lan_su_dung DESC
LIMIT 10;

-- Thuốc BVTV
SELECT 
    tb.ten_thuoc,
    nt.ten_nhom AS nhom,
    COUNT(lsc.id) AS so_lan_su_dung
FROM nongsan.lich_su_canh_tac lsc
JOIN nongsan.thuoc_bvtv tb ON lsc.thuoc_bvtv_id = tb.id
LEFT JOIN nongsan.nhom_thuoc_bvtv nt ON tb.nhom_thuoc_id = nt.id
GROUP BY tb.id, tb.ten_thuoc, nt.ten_nhom
ORDER BY so_lan_su_dung DESC
LIMIT 10;
```

## Kết Nối với Backend

### Flask + psycopg2

```python
import psycopg2
from psycopg2.extras import RealDictCursor

def get_db_connection():
    return psycopg2.connect(
        host="localhost",
        database="nongsan_db",
        user="postgres",
        password="your_password",
        cursor_factory=RealDictCursor
    )

# Sử dụng
@app.route('/api/vung-trong')
def get_vung_trong():
    conn = get_db_connection()
    cur = conn.cursor()
    cur.execute("SELECT * FROM nongsan.v_vung_trong_full")
    data = cur.fetchall()
    cur.close()
    conn.close()
    return jsonify(data)
```

### Node.js + pg

```javascript
const { Pool } = require('pg');

const pool = new Pool({
    host: 'localhost',
    database: 'nongsan_db',
    user: 'postgres',
    password: 'your_password',
    port: 5432
});

// Sử dụng
app.get('/api/vung-trong', async (req, res) => {
    const result = await pool.query('SELECT * FROM nongsan.v_vung_trong_full');
    res.json(result.rows);
});
```

## Migration & Backup

### Backup Database

```bash
# Backup toàn bộ
pg_dump -U postgres -d nongsan_db > backup_$(date +%Y%m%d).sql

# Backup chỉ schema
pg_dump -U postgres -d nongsan_db --schema-only > schema_backup.sql

# Backup chỉ data
pg_dump -U postgres -d nongsan_db --data-only > data_backup.sql
```

### Restore Database

```bash
# Restore
psql -U postgres -d nongsan_db < backup_20241227.sql
```

## Tối Ưu & Index

Database đã được tối ưu với các index sau:

- Index cho khóa ngoại (FK)
- Index cho các trường tìm kiếm thường xuyên (mã vùng, mã cơ sở...)
- Index cho các trường filter (trạng thái, tỉnh/huyện/xã...)
- Index composite cho các truy vấn phức tạp

## Lưu Ý Quan Trọng

1. **Bảo mật**: Đổi mật khẩu PostgreSQL trong production
2. **Performance**: Monitor query performance và thêm index khi cần
3. **Backup**: Thiết lập backup tự động hàng ngày
4. **Migration**: Sử dụng migration tool (Alembic, Flyway) cho production
5. **Validation**: Validate dữ liệu ở tầng application trước khi insert
